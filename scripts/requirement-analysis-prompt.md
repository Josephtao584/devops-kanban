# 需求分析 Prompt

把下面整段发给 LLM（如 `claude`），并在 `{在这里写你的需求}` 位置填入具体需求。

AI 会按需读取：
- `service-analysis/architecture.md` — 架构总览，先读建立全局视角
- `service-analysis/profiles/*.md` — 每个服务的详细画像，按需读取

---

```
你是一位熟悉我们系统的架构师。我给你一个新需求，请帮我分析影响面和改动点。

## 你有的资料

- 架构总览: service-analysis/architecture.md   （先读这个建立全局视角）
- 服务画像: service-analysis/profiles/*.md     （每个服务一个 .md，按需读取）

## 工作流程（请严格按顺序）

1. 先用 Read 读完 service-analysis/architecture.md，建立整体认知
2. 根据需求判断"可能涉及的服务"，用 Glob 列出 service-analysis/profiles/ 下的文件名做校对
3. Read 你判断涉及的每一个服务的 profile，确认技术栈、接口、数据模型、依赖关系
4. 如果读完发现还有遗漏的关联服务（被依赖方或上游调用方），回到第 3 步继续读
5. 所有依据收齐后，再开始输出分析

## 新需求

{在这里写你的需求}

## 输出格式

### 一、涉及的服务
按改动量从大到小列表，每条包含：服务名 / 本次改动要点 / 工作量（S/M/L）

### 二、调用链路
用箭头描述请求流转：caller → service → downstream，把关键分支点写清楚

### 三、接口变更
新增或修改的接口清单，标注是服务间 RPC 还是对前端/外部的 HTTP 接口

### 四、数据模型变更
涉及的表/字段/缓存 key/前端状态，谁加谁改

### 五、关联影响与风险
容易被忽略的旁路影响（消息/定时任务/权限/二方库连带升级等）

### 六、不确定点
读完资料后仍有疑问、需要我确认的地方，列清单

## 硬性要求

- 只依据上述文件做分析，不要臆造服务或接口
- 每个结论尽量标注依据来自哪个文件（如"据 order-service.md 第 X 节"）
- 如果 architecture.md 与某个 profile 冲突，以 profile 为准，并在"不确定点"里指出
```
